- [Background mode](https://developers.openai.com/api/docs/guides/background): `background:true`, polling GET `/v1/responses/{id}`, active states `queued` / `in_progress`. Background work temporarily retains response data; `store:true` explicitly requests retention, subject to project policy.

The generic Responses mechanism is documented; the Sol page does not separately certify background capability, and account/model acceptance remains unverified under the zero-call restriction. A rejection is retained and stops execution; there is no foreground fallback or model substitution. `scripts/sol-high-background.ts` reuses the installed SDK's `generateText`, Responses adapter, structured-output parsing, scene runtime validation and scene resolution. A small custom fetch adapter adds background creation and polling because the installed adapter exposes neither background creation nor retrieval. No dependency or second AI generation pipeline was added. It is a CLI development option only; the web route and production defaults are unchanged.

Missing usage stays unknown. Scene construction writes an UNAPPROVED local artifact and never imports a project.

An exclusive run directory prevents a second create, including after ambiguous acceptance. Each request has a 60-second transport timeout. Polling is bounded to approximately 15 minutes, then stops locally without cancelling generation. HTTP errors and transport failures stop immediately; queued-status polling is not resubmission. Failed/incomplete/cancelled terminal results retain their raw usage and are never accepted as scenes.

Residual limitation: if the initial create is accepted but its ID never reaches local disk, automated recovery is impossible; the directory stays locked against resubmission.
