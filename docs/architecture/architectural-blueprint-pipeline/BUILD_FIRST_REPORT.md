# Build-first generation and recoverable defects audit

20 October 2026, America/St_Lucia.

The `AI_V3_ARCHITECTURAL_BLUEPRINT` branch now returns **Complete**, **Draft — Needs Refinement**, or **Cannot Construct**. A supported property with localized defects can be constructed, displayed, edited and saved as a draft. Core architectural contradictions still return no scene. The flag remains disabled by default; this work does not change environment settings, activate provider access or deploy anything.

## Rejection trace and classification

The original route was fail-closed at each stage, including for some renderable, localized defects. Before this change, an internal door offset outside its boundary could prevent construction of the entire independent estate. Ordinary V3 validation already distinguished physical issues from fatal ones, but the independent adapter promoted every non-advisory detail finding to fatal; blueprint approvals and ingestion also stopped on any fatal blueprint finding.

1. **Routing/provider output:** `requestHouseEdit` resolves the existing project mode and revision. The server selects this branch only for new flat V3 generation with the exact flag value `1`. Terra returns one independent blueprint through the real SDK JSON parser. Invalid/truncated/abnormally terminated output is core-blocking. Unknown top-level fields, a second detailed scene, unsupported explicit brief geometry and missing requested features remain core-blocking. SDK transport retries remain zero.
2. **Schema and early preflight:** the strict schema, IDs/references/materials, program, building footprints, roof capability/pitch, declared entrance, storeys and explicit architectural choices remain mandatory. Initial planning still performs no full-scene compilation. The only early-preflight exception is an overlap between supported internal rectangular door cutouts; the contextual scene check subsequently decides whether it can be a draft.
3. **Lowering/approval:** V3 lowers the one design into ordinary scene semantics. Existing blueprint spatial/interior checks, compiler-policy checks, normalization comparisons and opaque in-process approval handles remain. Build-first approvals can carry specifically classified detail findings. Historical strict callers use the unchanged strict default. No serialized handle authorizes construction.
4. **Construction:** the build-first constructor uses the approved, normalized scene directly and runs ordinary scene validation, blueprint spatial/access checks, compiler policies, design consistency, opening and interior preflight, physical stair evidence, production compilation and complete component receipts. This explicit path avoids ingestion's old early rejection of draft-tolerable findings. The historical strict constructor still uses production ingestion. Nothing calls the old normalizer's reference repair to erase a draft defect. No authored component, location, material, footprint, requirement, host or opening is rewritten by draft acceptance.
5. **Deterministic correction:** route-owner selection envelopes are recomputed from authoritative route endpoints/waypoints. Contacts, approach normals, roof parts and route ribbons continue to derive from the same blueprint geometry. A failed mesh/component receipt triggers one fresh production compilation and receipt audit before rejection or draft acceptance. This repairs a transient derived mismatch without authoring geometry or consuming a provider call. Persistent core mesh failures still block.
6. **Brief and provider repair:** recognized missing requested architecture still rejects a completed or draft candidate. The existing single objective stair/waypoint correction remains available when construction is blocked and the protected-decision comparison permits it. There are at most two authoring calls, no third call, no detailed-scene authoring and no aesthetic follow-up. A viable draft returns immediately rather than spending a provider call on its local imperfections.
7. **Preview/client/persistence:** a draft is a successful response with ordinary editable V3 JSON and an explicit draft validation state; it is not the ephemeral failed-preview mechanism. Cannot Construct returns no JSON/model. The client keeps the live revision conflict check and calls `apply` only for a successful JSON response. Draft and Complete outcomes do not enter the V2 no-op branch. Project-store commits revalidate the current scene, store status/diagnostics in the same JSON and version, and reject invalid commits before changing state. Initial generation cannot replace an already designed project with a draft. Existing versions remain available.

## Draft contract and editing

`scene.metadata.architecturalValidation` contains `{version:1,status:'draft'|'complete',diagnostics}`. Each diagnostic retains its original code, message, severity and stable target IDs, plus its acceptance classification. Draft acceptance does **not** relabel fatal evidence as advisory. The independent input blueprint and approval are still not persisted as a second authority.

The viewport displays **Draft — Needs Refinement**, explicitly says the scene is not fully validated/certified, lists object diagnostics and offers revalidation. Diagnostics select their semantic targets. The inspector now edits internal door width/offset through the existing semantic operations. Ordinary object/material/JSON and local semantic editing remain available. A scene edit with an architectural-validation marker is accepted only after current-scene revalidation; repairing the last defect promotes the scene to Complete. A forged/removed metadata label cannot bypass the check on an already tracked project. Every commit refreshes diagnostics rather than trusting an old list.

Complete preserves the established supported construction guarantees: no remaining non-advisory objective findings and all required architecture, receipts, entrances and access checks pass. It means acceptance under this software contract, not an engineering certificate.

The implementation is intentionally conservative about major amenities, facade glazing and structural parts. Reclassifying a missing guard, roof, whole balcony or unusable sole stair as “detail” would violate the construction objective. Current draft acceptance does not make unsupported domes, tree layouts, variable-storey forms or bespoke geometry constructible.
