# Why the design-first mansion failed

The latest failure is a failure to select coordinated architecture before construction, with smaller software-contract defects. No construction response or render exists for this proposal. A stronger planning model is worth testing before another architectural refactor. This audit makes no claim to recover hidden reasoning or prove that a different model will design a beautiful building.

## Does the contract suppress creativity?

No rule requires rectangles, symmetry, three masses, a particular roof or storey count. Optional profiles, independent yaw and up to 300 anchors make a richer proposal expressible. Empty access arrays and capacity stages permit incomplete JSON to pass structural parsing, but semantic validation rejects missing interior access; those fields distinguish incompleteness rather than provide spatial intelligence. Labels and prose can still describe architecture absent from anchors. Adding more fields would not resolve that design failure.

There are real pressures: the planner receives the long construction vocabulary and retrieval before the final planning override; it must commit exact component geometry while considering architecture. Every anchor is immutable, so abstract mass reservations cannot later become hollow shells. Spaces are rectangular boxes on one referenced floor, and routes are lists of anchors rather than full navigation geometry. This makes complex rooms require decomposition and leaves profile usability unverified. These are genuine burdens and expressivity limits, but no controlled evidence establishes that they caused this composition. Do not relax fidelity to let a second call invent the missing design.

The current planning override explicitly requires suite boundaries/access even in exterior scope, while earlier general instructions defer bedroom/bathroom subdivision. The override resolves precedence but leaves avoidable cognitive ambiguity. This audit does not rewrite broad guidance or infer that the model was compelled to omit doors. The model explicitly deferred stairs despite the planning instruction requiring their selection.

## Existing representation

Existing offline cases cover compact family geometry (47 elements), waterfront developer composition (193), and constrained multilevel geometry (57). They demonstrate transport of independent roofs/slabs, multiple levels, rotated subordinate volumes, profile commitments, openings and facade/outdoor parts. Existing tests detect changed profiles, materials, omitted anchors and world-coordinate divergence. They are derived from existing scenes, not newly designed mansions and not examples sent to the model.

**The system already has the geometric vocabulary for a substantially sophisticated connected mansion.** There is no demonstrated need for a new layout compiler or geometry engine to fix this proposal's gaps, shells, doors and stairs. This is not proof of arbitrary freeform architecture, verified complete circulation or full interiors. One-floor rectangular space metadata, five material choices, fixed composite components, flat terrain, absent hydraulic simulation and unverified headroom constrain the ultimate product. A finished building with complete fit-out exceeds the current exterior-only experiment scope.

## Corrections actually made

Only `designProposal.ts` and focused tests change behavior:

- Space centre schema description now states world box centre and `centreY = floorTop + height/2`, matching the existing check. No new datum validator.
- Overhead references accept `plate` as well as `roof`: an upper slab can shelter a lower room. This fixes the demonstrated kind inconsistency. It does not certify coverage, clearance or shelter; arbitrary water still fails. Composite pavilion bounds are not a roof surface, so the description asks for explicit overhead parts instead of granting blanket acceptance.

No new architectural rules, scoring framework, validators, automatic repairs, model default or construction engine. The original response still fails its declared relationships. All its missing architecture remains missing. Tests exercise plate references across two existing configurations; no replacement mansion was constructed.

The ambiguous facing semantics and nominal roof-underside guidance are recorded rather than broadly rewritten: local descriptions are useful follow-up contract maintenance, but changing relationship behavior or renderer bounds would confound this model comparison. Their small discrepancies cannot explain missing suites/stairs.

## Recommendation

1. Latest failure: Terra selected an incomplete and internally contradictory design, rather than a rich proposal lost in construction.
2. Model: arrangement, absent access/boundaries, disconnected floors and geometry/prose contradictions. Software: overhead kind restriction, insufficient local datum semantics, remaining prompt ambiguity and incomplete verification coverage.
3. Existing geometry can express much better coordinated architecture; it does not certify complete habitable buildings.
4. No evidence that rectangular massing is mandatory. Exact component commitments burden planning, but their causal effect is unproved.
5. Only datum clarification and slab-overhead compatibility were demonstrated corrections. Further validators would principally improve rejection.
6. Do not treat Terra as a proven reliable premium architectural planner. Keep its configuration unchanged pending comparison; test Sol for planning specifically.
7. Most informative next live experiment: the single frozen-payload Sol planning call above, assessed against the retained Terra output before any construction call.
