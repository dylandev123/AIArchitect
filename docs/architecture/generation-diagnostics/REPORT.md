# Terra generation diagnosis — 28 October 2026

The largest demonstrated quality loss is in the authored programme, composition and its translation into connected functional geometry. The executor does not turn a developed mansion into a bungalow. Successful serialization and zero hard geometry errors have repeatedly been mistaken for architectural completion. These conclusions concern observable outputs, not Terra's private reasoning.

This investigation made **zero provider calls**, used no database connection, and ran no migrations, commits or deployment. Five retained paid outputs were replayed with network disabled. Existing screenshots were inspected; they were not presented as newly rendered captures. Historical source files were read and hashed, never rewritten. [Replay index](index.json) distinguishes present-day acceptance from historical status.

## Failure classification and confidence

- **Brief interpretation:** unknown for redacted original briefs. Mediterranean identity is observably responsive to its retained brief; extravagant price language alone is not a measured residential programme.
- **Knowledge retrieval:** delivery is established where context/wire captures exist. No controlled counterfactual demonstrates whether a different selection would improve architecture. Historical missing traces cannot be reconstructed by running today's retrieval.
- **Architectural concept selection:** low three-block organisation is explicit in the coordinated villa; the courtyard concept is coherent at topology level. Their visual development remains weak.
- **Programme and scale planning:** no complete room/area allocation or circulation construction substantiates the estate claims. The bungalow's small upper accommodation is directly measurable; exact original brief alignment remains unknown.
- **Design-to-operation translation:** failed Redesign supplies no construction. Other outputs claim shelter, access and rich development without the corresponding geometry.
- **Construction geometry:** old pool-coping conflicts and current door/opening alignment defects are concrete. Current rejected transactions roll back atomically; they do not shrink a building.
- **Spatial relationship coordination:** courtyard floor/wall junctions and the villa gallery/thresholds are unresolved. Bounding-box warnings alone are not a navigability verdict.
- **Rendering:** retained images broadly match authored massing. No evidence that the renderer erased a substantial residence. Thin-component conventions and flat staging exist, but do not explain missing rooms and upper volumes.
- **Functional completeness:** entrances alone do not establish connected rooms, stairs, sanitary spaces, services or usable upper access. These remain materially incomplete.
- **Visual architectural quality:** inspected bungalow, villa and court renders show weak entrance hierarchy, sparse facade depth and disproportionate roof/volume relationships. This is a visual assessment supported by the listed screenshots, not a validator score.

## Answers and next measurable experiment

1. **Why past houses were underdeveloped:** Terra authored sparse compositions and incomplete programmes; later examples added stronger intent prose without consistently constructing its promised relationships. Assembly adoption helped construction mechanics without fixing architectural development.
2. **Largest quality loss:** programme/compositional development and design-to-operation translation. A numerical loss percentage cannot be inferred from these records.
3. **Executor accuracy:** exact add preservation is asserted for the bungalow's staging. Current accepted replays implement the recorded transactions and assembly expansions. No observed automatic simplification explains the weak houses. This is not a universal proof of renderer or executor fidelity for every possible operation.
4. **Knowledge effect:** Mediterranean court/hip-roof choices and explicit `designDecisions` are consistent with supplied knowledge. Some citations fail their required-kind checks. Delivery and declared use are observable; causal benefit and quality improvement are not established. The basic response predates the relevant retained trace.
5. **Underused available capabilities:** meaningful multi-level floor area, supported projecting terraces, connected articulated facade bays, parent transforms, angled wings, primitives for stairs/voids and coordinated rooms. These capabilities do not guarantee quality. Assemblies are now used substantially, so adding more assembly recipes is not the evidence-backed first response. True arches and automatic interiors/stairs remain unavailable.
6. **Highest-potential change:** make the next first-pass evaluation judge **realized programme and circulation against the already explicit concept**, rather than judging acceptance or citations. First specify the actual accommodation, desired area range and principal spatial relationships in the experiment brief; monetary property value is not a building programme. Compare the unchanged engine's first output against those requirements using stable component IDs and matched views. This is a recommendation for a controlled experiment, not a proven prompt remedy. No speculative prompts, recipes or validators were added here.
7. **Unobservable:** hidden model reasoning, discarded concepts, causal knowledge influence, missing original briefs/instructions, historically applied browser state, and visual quality without a matching render. Explicit intent cannot be backfilled honestly. The next response must record any programme/scale decisions that are currently absent; prose still needs constructed evidence.

Keep the model, engine and budgets fixed for that experiment. Record the brief and actual chosen programme; inspect connected access, substantial primary/secondary volume proportions, intended-to-constructed element references, omissions, provider status and fixed-camera images. Treat these as review measurements rather than adding rejection rules. Do not spend another generation until the retained evidence and experiment specification are reviewable.

## Implemented diagnostics and use

The existing homepage `/api/ai/scene` path now joins records by response UUID:

- Existing redacted response artifact remains compatible.
- `.wire.json` stores the exact UTF-8 request and original HTTP response body as strings, before SDK parsing, with HTTP status and no auth headers. `.provider.txt` separately preserves exact SDK output text. No original response is repaired, normalized or redacted in these private files.
- `.diagnostics.json` contains exact messages, output schema, SDK response metadata/usage/status, and execution provenance. System/developer wire instructions and capabilities are captured in the wire request; selection/exclusion evidence remains in the existing knowledge trace. Provider-call reporting is zero for pre-provider failures.
- Existing Architectural warnings/editor UI gains Generation diagnostics, selected component provenance, and ordered operations. A response ID persists with the scene, and local development can reload the saved report. Raw request/response bodies stay server-only. Existing project versions retain subsequent manual changes; reports show the selected element's current state alongside generation state. Later model edits link to the preceding generation ID.
- Existing Visual review gains **Export diagnostic screenshots (offline)**. It uses the same four-view capture component, exporting actual PNG data, camera poses, scene snapshot, capture time and response ID as one JSON file. It never invokes a review model. Export is explicit; automatic screenshots are not claimed.

Private captures contain unredacted briefs/reference images, live outside source control in `.data`, use exclusive writes and owner-only file permissions, and should stay local. Retention failure does not invalidate constructed geometry, but logs a diagnostic storage failure. The development report endpoint rejects malformed IDs and is disabled outside development.
