# Terra direct-scene architectural planning

Generation now requires an `architecturalPlan` before `operations` in the structured response. This stays within the existing single provider request, construction primitives, geometry validators and limits. The plan records intended scale and its justification, levels, enclosed floor area, named residential/outdoor spaces and their approximate sizes, arrival/circulation, volume hierarchy, relationships/views, and roof/facade/material identity. Instructions explicitly use budget as an ambition cue, without pricing formulas, templates or minimum element counts.

Each space references floor plates and enclosure/roof evidence; commitments reference entrance, circulation, primary/subordinate volumes, roofs, facades and terraces. The model is instructed to resolve the design first, construct the whole plan, and self-review before returning. Floors are allocated to non-overlapping space areas; walls and roofs can serve multiple spaces.

The canonical API requires the plan even if the provider adapter bypasses schema validation. The existing resolver first executes and validates the proposed transaction, then audits the result. Missing/wrong-kind references, missing core commitments, duplicate/overlapping floor accounting, inconsistent level datums, and floor areas differing by more than 15% from approximate plan targets are rejected. Interior perimeter samples need nearby enclosure (or an adjacent planned interior floor) and overhead coverage. Parent transforms and arbitrary yaw are accounted for. Rejection returns 422 and does not commit geometry. The client retains the plan when revalidating the response. Both scene API URLs use this handler.

Legacy scene replay remains supported without requiring retrospective plans. Scoped edits can omit a plan and retain existing atomic geometry validation. No geometry is repaired, removed, filled in or resized by the architectural audit.

These are evidence checks, not a certified net-area calculator, full enclosure proof, semantic brief evaluator, engineering certification or architectural quality score. Sampled enclosure can miss gaps. Circulation usability, actual internal room layouts, quality of hierarchy, view relationships and stylistic coherence still need visual review. Requested missing capabilities must be disclosed. This implementation has offline regression evidence; it does not establish that a new live mansion meets the design ambition.
