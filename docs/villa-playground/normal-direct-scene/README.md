# Normal Villa Playground integration audit

The actual normal **New design → Generate villa** button used the legacy villa configuration system. The independent scene engine existed, but the button's handler still called `fetchVillaRequest` (`/api/ai/villa`) and `resolveVillaResult`. Changing the default page to OperationStudio did not connect this existing workflow: compositions, recovered responses and legacy URLs still opened that handler. The homepage/workspace already had separate direct-scene routing in this checkout; that did not repair this playground button.

Before this fix, generation sent `{prompt,mode,site?}` to `fetchVillaRequest`; edits sent `current: authored ?? config`. The normal generate payload did **not** include the displayed preset/current configuration. This rules out a preset being passed implicitly as the generation baseline. An optional fixed site previously constrained the old generation.

House-level builders, footprint levels, wings, stacks and facade defaults control these designs.

## Changes in this task

1. Restored the normal playground page/button workflow rather than relying on bypassing it through a default-page redirect. Explicit Casa Ladera, composition, offline and retained-response routes remain supported.
2. The actual normal Generate villa handler now passes its brief to the existing `OperationStudio` via `initialBrief`, without calling the old endpoint. The studio executes a single generate request through `/api/ai/scene`; the URL remains the normal playground URL. Later Generate villa and Apply change actions use the same direct scene system.
3. Kept legacy configuration edits/recovery on their existing handlers. Removed old fixed-site controls from the new-generation form because their configuration contract does not apply to scene operations. No replacement site schema was added.
4. Added Legacy villas / Return to direct scene navigation that preserves the legacy viewer state, current direct scene and in-session undo history. Reload restores the stored direct scene via Return to direct scene. Restored scenes are not presented as new provider generations. No automatic AI request is made on restoration.
5. Named comparison mode Current direct scene, and added an explicit undoable Load Casa Ladera action. Selecting Villa Solana is a comparison preview and does not overwrite the direct scene. Commit uses the current scene snapshot, so asynchronous generation does not capture an obsolete undo baseline.
6. Added mocked server boundary regression tests and normal-button browser regression. Updated the previous direct-scene capture script's endpoint/button selectors to match the authoritative implementation.

Casa Ladera can be loaded and undone.

Artifacts: `normal-generated-aerial.png`, `normal-generated-poolside.png`, `legacy-solana-preserved.png`, `restored-direct-scene.png`, and `browser-checks.json`. Tests cover both the browser transport contract and the real server resolver separately; the browser mock intentionally does not contact the provider.

Final checks passed: 64 tests across scene model/resolver/roofs, the real scene API with mocked provider, project history, legacy composition and legacy API; `npm run typecheck`; focused ESLint; and the complete browser script (3 intercepted requests, 43 rendered operation groups, zero page or console errors). Screenshots were visually inspected. Repeating the same normal brief after switching also issues a fresh scene generation and supports undo.

## Remaining restrictions

No legacy footprint, wing, stack, cardinal placement, house-family, facade rhythm or floor-alignment rules apply to new direct designs. Legacy designs retain their existing restrictions and edit system. The existing scene engine still limits geometry to its implemented primitives and yaw rotations; flat/gable/hip roofs, one opening per wall element, five materials, no arbitrary curved/polygonal solids/mesh/CSG, no automatic stairs/circulation/engineering. Integrity budgets remain 400 elements, 800 operations, 40 panels, finite bounded coordinates/dimensions and valid acyclic IDs/attachments. Garden staging is presentation context, not a newly generated landscape. Playground stores one current scene; export JSON or use saved projects for durable multiple designs. In-session playground undo is preserved across comparison switches, but its history does not survive full reload; project version history does.

No architecture engines, schemas, V3 changes, migrations, commits or deployment were added by this task. The checkout already contained extensive unrelated changes; those were preserved.
